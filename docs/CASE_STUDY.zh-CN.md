# 案例：一次抓取失败之后，如何找相似场景并补充训练样本

[English](CASE_STUDY.md) | [简体中文](CASE_STUDY.zh-CN.md)

假设机器人在桌面拿起物体时滑落，工程师保存了失败前后的画面，希望回答：
以前遇到过哪些相似环境？失败集中在哪类物体或阶段？哪些片段值得加入下一轮训练？
这是业务场景假设，不是对 DROID-100 中某集成败的断言。

## 数据准备

导出流程把 100 集的状态、动作、视频和元数据写到 OSS Lance；SigLIP2 为采样帧生成
768 维向量，再构建 cosine 向量索引。默认逐帧有 96,636 条图像向量，三路视频各自保留。
DROID-100 适合验证整个流程；它不是海量数据本身，也不保证包含足够多的目标抓取失败。

state/action 都是 7 维源记录；该版本只标注 motor_0 到 motor_6，不能未经核实把某一维
解释为夹爪开度或某个关节角。`next.reward` 和 `next.done` 也不能直接推导完整抓取失败标签。

## 1. 找到相似场景

将现场关键图片交给 `doris.prepare_query --image`，或使用已经导出的失败关键帧 sample-id。
前者运行固定版 SigLIP2，后者直接取存储的向量。Doris 的 `vector_search()` 使用 Lance 索引
返回相似帧，按 episode 去重后保留最多 50 个复核候选。

同一相机视角和模型版本在检索前过滤；不先筛选失败，保留相似条件下的成功对照。
视觉相似只说明画面内容相近，不证明动作过程或失败原因相同，仍需回看视频。

## 2. 关联动作与视频，复核一次完整尝试

`sample_id = episode:camera:frame_index` 定位图像向量；`media_id = episode:camera`
关联该路原始视频；`(episode_index, frame_index)` 关联同一时间步的 state/action。
`episode_index` 关联任务与 episode 元信息。三路相机共用同一组状态/动作时间步。

查询给出关键时刻及初始前后窗口，使用提取工具取出 MP4，再人工标注完整尝试的起止秒数。
例如区分未接触、接触后滑落、搬运途中掉落；无法确认的结果标记 unknown。
没有可靠的复核标签时，流程只能提供相似候选，不能声称完成了失败原因分析。

## 3. 用 Doris 分析失败分布

SQL 首先显示检索量、复核量和可用成败标签量，再按物体和场景分组计算：

`失败比例 = 已复核且质量可用的失败尝试数 / 已复核且质量可用、成败已知的尝试数`

进一步按 failure_stage、failure_reason 汇总，以定位值得继续检查的问题群。
这是一份由相似度检索选择出的样本，不是随机抽取的线上流量；比例不代表线上总体失败率，
标签统计也不能单独证明因果。没有真实标签时不展示虚构的百分比。

## 4. 筛选值得补充训练的片段

候选必须已复核、任务匹配、质量可用、起止时间有效，并且有可靠的数据切分与训练登记。
同一采集场景/会话不能跨训练和评估集合；已使用过的训练样本排除。
每个物体/场景/训练用途桶内按场景组去重并设置数量上限，避免近重复数据占满补充集。

相似环境下的成功片段可作为行为克隆正例；失败片段可用于失败分类、价值函数或人工诊断。
若要学习失败后的恢复动作，需要额外定位恢复成功的动作区间，当前查询不会自动标注它。
“值得训练”在这里表示通过规则筛出的候选，收益仍需通过后续训练和独立评估验证。

## 分析结果与执行入口

分析最终输出三类结果：相似场景复核清单、标签覆盖率和失败分布、带时间区间和用途的训练候选。
